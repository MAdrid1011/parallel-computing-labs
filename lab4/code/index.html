    Lab4 核心代码讲解¶

    Lab4 继续计算 C = A × B，但每个 MPI 进程只保存一部分矩阵。A 的本地行决定了本进程负责哪些输出，而这些行的列索引决定了它需要哪些 B 行。围绕这一依赖关系，可以把实现分为数据划分、数据交换和本地计算三个部分。

    1. 每个进程负责哪些行？¶

    src/distribution.cpp 中的 make_distribution 计算所有进程的行边界，再取出当前 rank 对应的区间。

    if (cfg.partition == "nnz")
        for (std::size_t i = 0; i < cfg.m; ++i)
            prefix[i + 1] = prefix[i] + row_nonzeros(i, cfg.m, cfg.k, cfg.nnz_per_row, cfg.profile);
    for (int p = 0; p <= d.ranks; ++p) {
        d.a_offsets[p] = cfg.partition == "rows" ? cfg.m * p / d.ranks
            : static_cast<std::size_t>(std::lower_bound(prefix.begin(), prefix.end(), prefix.back() * p / d.ranks) - prefix.begin());
        d.b_offsets[p] = cfg.k * p / d.ranks;
    }
    d.a_offsets.back() = cfg.m;
    for (int p = 0; p < d.ranks; ++p) {
        d.b_counts[p] = static_cast<int>((d.b_offsets[p + 1] - d.b_offsets[p]) * cfg.n);
        d.b_displacements[p] = static_cast<int>(d.b_offsets[p] * cfg.n);
    }
    d.row_begin = d.a_offsets[d.rank]; d.row_end = d.a_offsets[d.rank + 1];
    d.b_begin = d.b_offsets[d.rank]; d.b_end = d.b_offsets[d.rank + 1];

    a_offsets[p] 是进程 p 所负责的 A 行段的起点，右端是 a_offsets[p+1]，同一进程也负责 C 的对应行。partition=rows 按行数均分；partition=nnz 先构造非零数前缀和，再用 lower_bound 寻找接近各份目标工作量的行边界。它不会拆开一行，因此非零数也不保证完全相等。

    B 按行数均分，与 A 选择哪种划分方式无关。b_counts 计算每个进程持有多少个 B 元素，b_displacements 给出这些元素在完整 B 中的起始偏移。两者都以 MPI_DOUBLE 元素为单位，不是字节数。

    void broadcast(const CsrMatrix& a, DenseMatrix& c, Workspace& w, const Config& cfg,
                const Distribution&, MPI_Comm comm, RankStats& stat) {
    auto start = MPI_Wtime();
    MPI_Bcast(w.full_b.values.data(), static_cast<int>(w.full_b.values.size()), MPI_DOUBLE, 0, comm);
    stat.mpi_s = MPI_Wtime() - start;
    start = MPI_Wtime();
    multiply_tiled(a, w.full_b, c, w.blocks, cfg.tile);
    stat.compute_s = MPI_Wtime() - start;

    MPI_Bcast 返回后，每个进程都有相同的 w.full_b。本地 A 的列索引可以直接索引它，计算结果只写入本地 C。

    void allgather(const CsrMatrix& a, const DenseMatrix& b, DenseMatrix& c, Workspace& w,
               const Config& cfg, const Distribution& d, MPI_Comm comm, RankStats& stat) {
    auto start = MPI_Wtime();
    MPI_Allgatherv(b.values.data(), static_cast<int>(b.values.size()), MPI_DOUBLE,
                   w.full_b.values.data(), d.b_counts.data(), d.b_displacements.data(), MPI_DOUBLE, comm);
    stat.mpi_s = MPI_Wtime() - start;
    start = MPI_Wtime();
    multiply_tiled(a, w.full_b, c, w.blocks, cfg.tile);
    stat.compute_s = MPI_Wtime() - start;

    b_counts 说明每份数据有多长，b_displacements 说明它应该放到完整 B 的哪里。两个版本在通信后使用同一个 multiply_tiled 内核，因此比较时主要关注获得 B 的方式及其开销。

    如果本地 A 只引用少量不同的列，收集完整 B 就会传来许多用不到的数据。src/communication_plan.cpp 先从本地 A 的列索引构造需求集合：

        auto columns = a.col_idx;
    std::sort(columns.begin(), columns.end());
    columns.erase(std::unique(columns.begin(), columns.end()), columns.end());
    std::vector<std::uint32_t> local_rows, requested_rows;
    std::vector<int> receive_rows(d.ranks, 0), send_rows(d.ranks, 0);
    for (auto column : columns) {
        if (column >= d.b_begin && column < d.b_end) local_rows.push_back(column);
        else {
            const auto owner = static_cast<int>(std::upper_bound(d.b_offsets.begin(), d.b_offsets.end(), column) - d.b_offsets.begin() - 1);
            ++receive_rows[owner]; requested_rows.push_back(column);
        }
    }
    const auto receive_offsets = displacements(receive_rows);

    排序和去重使一个 B 行只请求一次，即使本地 A 中有很多非零元素引用它。落在 [b_begin,b_end) 的行已经在本进程，其他行则根据 b_offsets 找到所属进程，并累计需要向它接收的行数。

    随后，程序先交换“需要哪些行”的编号，让每个进程知道应该发送自己的哪些行。收到的实际 B 数据保存在 needed_b 中：前部放本地所需行，后部放远程所需行。由于行号已经压缩，计划中的 slot 会把 A 的全局列号改写为 needed_b 中的槽号。

    例如，本进程只需要全局 B 的第 1、7、9 行，且第 1 行属于自己，那么 needed_b 可以依次保存这三行。相应的 A 列号会从 1、7、9 改成 0、1、2，原有乘法内核因而仍能通过列索引找到正确数据。

    pack_send_rows 复制当前所需的本地 B 行，并按发送计划打包其他进程请求的行。MPI_Alltoallv 允许各进程之间交换不同长度的数据；接收指针跳过本地前缀，将远程行直接写入预留的后部区域。通信完成后，h.all 使用改写后的列索引完成乘法。

    请求行号的交换与索引改写属于准备阶段，计入 setup_s；每轮实际数据的打包、交换和计算计入 elapsed_s。因此，receive_bytes 描述的是 B 数据的逻辑字节数，没有把计划元数据或 MPI 协议开销算进去。

    4. Overlap 在等远程行时计算什么？¶

    准备阶段还把 A 的非零元素分成 h.local 和 h.remote：前者只引用本地 B，后者引用需要接收的远程 B。两部分的行数相同，可以分别计算并累加到同一个 C。

        MPI_Request request;
    start = MPI_Wtime();
    // Local entries read only the local prefix of needed_b. The receive writes
    // its remote suffix, which is not read until the request has completed.
    MPI_Ialltoallv(h.send_values.data(), h.send_counts.data(), h.send_displacements.data(), MPI_DOUBLE,
                   h.needed_b.values.data() + h.local_b_rows * cfg.n,
                   h.receive_counts.data(), h.receive_displacements.data(), MPI_DOUBLE, comm, &request);
    stat.mpi_s = MPI_Wtime() - start;
    start = MPI_Wtime();
    multiply_tiled(h.local, h.needed_b, c, w.blocks, cfg.tile);
    stat.compute_s = MPI_Wtime() - start;
    start = MPI_Wtime();
    MPI_Wait(&request, MPI_STATUS_IGNORE);
    stat.wait_s = MPI_Wtime() - start;
    stat.mpi_s += stat.wait_s;
    if (!h.remote.values.empty()) {
        start = MPI_Wtime();
        multiply_tiled(h.remote, h.needed_b, c, w.blocks, cfg.tile, true);
        stat.compute_s += MPI_Wtime() - start;

    这里的先后关系决定了正确性：

    1. MPI_Ialltoallv 发起交换后返回一个 request，通信仍可能在进行。
    2. multiply_tiled(h.local, ...) 只读取 needed_b 的本地前缀；通信接收只写远程后缀，两者的访问范围不冲突。
    3. MPI_Wait 确认请求完成，此后才能读取远程部分。
    4. 最后的 true 表示把远程贡献加到已有 C，而不是覆盖此前算出的本地贡献。

    如果省略最后的累加，本地部分就会丢失。另一方面，使用非阻塞接口只创造了重叠的机会：实际收益取决于本地可计算工作量，以及 MPI 实现能否在计算期间推进通信。wait_s 记录到达 MPI_Wait 后还要等多久，不能仅凭调用了 MPI_Ialltoallv 就认定通信已被隐藏。

    5. 总时间为什么取最慢进程？¶

    源码：Lab4/src/benchmark.cpp · L68–L70（节选）

    68
69
70
            stat.rank_elapsed_s = MPI_Wtime() - start;
        double elapsed = 0;
        MPI_Reduce(&stat.rank_elapsed_s, &elapsed, 1, MPI_DOUBLE, MPI_MAX, 0, comm);

    每个进程记录自己完成本轮交换与计算的耗时，再用 MPI_MAX 汇总。整个结果需要所有进程共同完成，所以一个进程提前结束，并不能让本轮计算提前结束。

    按照操作步骤比较时，可以先用 nnz 与 rank_elapsed_s 看 A 的工作量是否均衡，再用 local_nnz、remote_nnz 和 receive_bytes 看数据依赖。最后比较 Halo 与 Overlap 的 elapsed_s 和 wait_s，判断本地计算是否提供了足够的重叠空间。汇总的各阶段最大值可能来自不同 rank，不能直接相加还原总时间。
