# Lab1 核心代码讲解

Lab1 的几种实现都计算 `C = A × B`。它们算出的结果相同，区别在于把计算分成哪些任务，再把任务交给哪些线程。行块、列块和线程数分别出现在这个过程的不同位置，可以用同一个小矩阵把它们联系起来。

从程序入口看，`src/main.cpp` 读取配置后进入 `benchmark`，生成 A、B 并准备行块，再根据 kernel 选择计算函数。每次计算从清零的 C 开始，最后由所选内核填入完整结果：

```text
准备 A、B 和行块 → 清零 C → 选择计算内核 → 填写 C
                               ├─ serial
                               ├─ parallel_rows（Rows / Dynamic）
                               ├─ parallel_balanced（NNZ blocks）
                               └─ parallel_tiled（Tiled）
```

## 1. 从一行输出的计算开始

考虑下面两个矩阵：

```text
A = [ 2  0  0 ]       B = [ 1   2   3   4 ]
    [ 0  3  0 ]           [ 5   6   7   8 ]
    [ 4  0  5 ]           [ 9  10  11  12 ]
```

A 有 3 行、3 列，B 有 3 行、4 列，所以 C 有 3 行、4 列。计算 C 的一行，就是用 A 这一行的元素，分别乘 B 的对应行，再相加：

```text
C 的第 0 行 = 2 × B 的第 0 行
            = [ 2   4   6   8 ]

C 的第 1 行 = 3 × B 的第 1 行
            = [ 15  18  21  24 ]

C 的第 2 行 = 4 × B 的第 0 行 + 5 × B 的第 2 行
            = [ 49  58  67  76 ]
```

A 中的零不会贡献结果，因此程序只保存和遍历非零元素。按行排列后，这个 A 的 CSR 数组为：

```text
values  = [2, 3, 4, 5]       非零元素的值
col_idx = [0, 1, 0, 2]       每个非零元素在 A 中的列号
row_ptr = [0, 1, 2, 4]       每行从 values 的哪里开始，最后一个数是结束位置
```

例如，第 2 行从位置 `row_ptr[2]=2` 开始，到位置 `row_ptr[3]=4` 之前结束，因此取出 values 中的 4、5，以及 col_idx 中的 0、2。下面的循环正是沿着这个对应关系计算：

{{SOURCE {"path": "Lab1/include/detail/row_kernel.hpp", "start": "    for (std::size_t i = begin;", "end": "                output[j] += value * input[j];"}}}

`i` 确定 A 和 C 的当前行。`p` 遍历这一行的非零元素，`a.col_idx[p]` 给出应当读取 B 的哪一行。最里面的 `j` 遍历输出列：对第 2 行来说，先把 `4 × B[0,j]` 加入输出，再加上 `5 × B[2,j]`。C 在开始计算前已经清零。

`omp simd` 允许编译器把不同列的乘加并排执行。它组织的是同一段列循环内部的运算，后面的线程分工则决定由谁执行哪一段任务。

Serial 让一个线程依次完成所有行。后面的几种实现保留这个计算关系，逐步改变任务的组织方式。

## 2. Rows 和 Dynamic 使用相同的行任务

按行并行时，这个例子共有 3 个任务：计算 C 的第 0 行、计算第 1 行、计算第 2 行。每个任务都计算自己这一行的全部 4 列。

如果使用两个线程，两个线程会共同完成这 3 个任务。**任务数由问题的划分决定，线程数决定有多少个执行者；一个线程可以先后执行多个任务。**

Rows 在开始时就把行任务分给线程。Dynamic 仍然以一行为任务，但线程完成手头的一行后，会继续领取尚未完成的行。两者的任务内容相同，分配时机不同。

在 `parallel_rows` 中，循环的一次迭代就是一个行任务：

{{SOURCE {"path": "Lab1/src/spmm_parallel.cpp", "after": "void parallel_rows(", "start": "        #pragma omp for schedule(runtime) nowait", "end": "            detail::accumulate(a, b, c, i, i + 1, 0, b.cols, local);"}}}

传给 `accumulate` 的 `i, i+1` 只覆盖当前一行，`0, b.cols` 覆盖全部输出列。不同任务写 C 的不同行，所以可以共同读取 A、B，而各自独立写输出。

`run.py` 中的名称与 C++ 配置对应如下：

| 名称 | 选择的内核 | 调度方式 | 一次领取的内容 |
|---|---|---|---|
| Rows | `rows` | `static` | 开始时分配行任务 |
| Dynamic | `rows` | `dynamic`，`chunk=1` | 每次领取 1 个行任务 |

源码中的 `schedule(runtime)` 读取运行参数设置的调度方式，因此这两个名称会进入同一个函数。行中非零元素较多时，这一行需要做的乘加也较多；Dynamic 允许较早完成任务的线程继续领取其他行。

## 3. NNZ blocks 把若干完整的行合成一个任务

上面的 A，三行分别有 1、1、2 个非零元素。如果设置 `block_nnz=2`，程序会从上到下累计非零数：

```text
第 0 行：1 个非零元素 ┐
第 1 行：1 个非零元素 ┘ 合成行块 0，共 2 个
第 2 行：2 个非零元素 ── 形成行块 1，共 2 个
```

于是，原来的 3 个行任务变成 2 个行块任务。每个行块仍然计算自己覆盖的行的全部输出列。用任务编号标记 C 中各位置的归属，可以画成：

| C 的位置 | 第 0 列 | 第 1 列 | 第 2 列 | 第 3 列 |
|---|:---:|:---:|:---:|:---:|
| 第 0 行 | ① | ① | ① | ① |
| 第 1 行 | ① | ① | ① | ① |
| 第 2 行 | ② | ② | ② | ② |

图中的数字表示任务，不是矩阵的计算结果。第一个任务负责前两行，第二个任务负责最后一行。虽然行数不同，两个任务都处理 2 个非零元素，并各自更新 4 列输出，因而乘加次数相同。

行块由下面的函数构造：

{{SOURCE {"path": "Lab1/src/partition.cpp", "start": "std::vector<RowBlock> partition_rows", "end": "    return blocks;"}}}

`begin` 是当前块的第一行，`row_ptr[i+1]-row_ptr[begin]` 是这一块累计的非零数。达到目标后保存这个行区间，再从下一行开始构造下一块。尾部不足目标值的行也会形成一个块。

这个过程保留完整的行。如果某一行自身就有 5 个非零元素，即使目标是 2，这一行也会整体进入一个块。因此，`block_nnz` 表示每块的目标非零数，不是块的行数，也不是绝对上限。

`parallel_balanced` 随后遍历块编号，把行块交给线程：

{{SOURCE {"path": "Lab1/src/spmm_parallel.cpp", "after": "void parallel_balanced(", "start": "        #pragma omp for schedule(runtime) nowait", "end": "            detail::accumulate(a, b, c, blocks[task].begin, blocks[task].end, 0, b.cols, local);"}}}

与 Rows 相比，传入的行范围变成了一个块的起止行，列范围仍是 `0` 到 `b.cols`。

## 4. Tiled 在行块上继续划分输出列

现在沿用刚才的两个行块，设置 `tile=2`。C 一共有 4 列，因此每个行块可以再分成“前 2 列”和“后 2 列”两份：

| C 的位置 | 第 0 列 | 第 1 列 | 第 2 列 | 第 3 列 |
|---|:---:|:---:|:---:|:---:|
| 第 0 行 | ① | ① | ② | ② |
| 第 1 行 | ① | ① | ② | ② |
| 第 2 行 | ③ | ③ | ④ | ④ |

任务①计算前两行的前两列，任务②计算前两行的后两列；任务③和④分别计算最后一行的前、后两列。两个行块、每块两个列块，一共形成 4 个任务。

因此，`block_nnz` 与 `tile` 可以一起使用：前者决定行怎么组成块，后者决定每个块一次处理多少输出列。即使一个行块只有一条很长的行，也能通过输出列划分成多个任务。

源码用两层循环组合这两个方向：

{{SOURCE {"path": "Lab1/src/spmm_tiled.cpp", "start": "        #pragma omp for collapse(2)", "end": "                register_block(a, b, c, blocks[block].begin, blocks[block].end, first, last, local);"}}}

`block` 选择行块，`panel` 选择列块，二者共同确定一个输出矩形。`collapse(2)` 让 OpenMP 分配这些组合任务；`min` 把最后一个列块截到矩阵边界。不同矩形没有重叠的输出位置，因此可以独立计算。

## 5. 列块内的局部累加

以任务③为例，它负责 `C[2,0]` 和 `C[2,1]`。这两个结果可以在局部数组中逐步算出：

```text
初始部分和                       [ 0,  0]
加入 4 × B 第 0 行的前两列        [ 4,  8]
再加入 5 × B 第 2 行的前两列      [49, 58]
最后把 [49, 58] 写入 C 的对应位置
```

Tiled 使用下面的微内核保存这一小段部分和：

{{SOURCE {"path": "Lab1/src/spmm_tiled.cpp", "start": "template<std::size_t Width>", "end": "    for (std::size_t lane = 0; lane < Width; ++lane) output[lane] = sums[lane];"}}}

`sums` 开始为零。每读取一个 A 的非零元素，就更新这段输出的部分和；这一行的非零元素全部处理完，才写回 C。实际代码优先按 32 列、8 列计算，再处理更小的尾段。刚才宽度为 2 的例子会使用 `Width=2`。

这里有两层大小：`tile` 决定交给线程的列块有多宽，`Width` 决定微内核一次保留多少列的部分和。例如 `tile=128` 的任务会在内部多次调用较小的微内核。Tiled 除了增加列任务，也使用了这种局部部分和的写法。

## 6. 各个参数在计算中的位置

| 参数 | 改变什么 | 对刚才例子的影响 |
|---|---|---|
| `m`、`k`、`n` | A 为 M×K，B 为 K×N，C 为 M×N | 例子中分别为 3、3、4 |
| `nnz-per-row`、`profile` | 生成 A 时的非零数量和分布 | 改变要处理的非零元素；各版本在相同输入下求同一个结果 |
| `threads` | 执行任务的线程数 | 2 个线程可以先后完成 4 个 Tiled 任务 |
| `block-nnz` | NNZ blocks、Tiled 中的行块目标大小 | 设为 2，前两行合为一块，最后一行一块 |
| `tile` | Tiled 中一个列块的宽度 | 设为 2，每个行块再分成两份 |
| `schedule`、`chunk` | 任务怎样交给线程，以及一次分配几个任务 | 在 Rows 中任务是一行；在 NNZ blocks 中是行块；在 Tiled 中是输出矩形 |

Serial 依次计算全部行；Rows 与 Dynamic 使用行任务；NNZ blocks 把行组成块；Tiled 再把每个行块按输出列划开。`block-nnz` 参与后两种实现，`tile` 参与 Tiled，设置这些参数时可以对照相应的循环看任务怎样变化。
