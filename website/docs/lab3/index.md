# Lab3：OpenMP 直方图

前两个实验让不同任务写各自的输出位置。现在我们来处理另一种情况：多个线程需要更新同一个计数。

## 1. 实验背景

直方图用一组计数表示各个值出现的次数。输入中的一个整数 v 对应第 v 个桶（bucket）：

```cpp
counts[v] += 1;
```

多个线程可以各自读取一段输入，但它们读到的值可能相同，因而需要更新同一个 `counts[v]`。这时要考虑共享更新的正确性，以及协调更新需要付出的时间。

## 2. 实验目标

1. 说明普通的 `+= 1` 为什么不能直接作为多个线程的共享更新。
2. 理解全局临界区、原子加和分段锁的保护范围。
3. 说明热点输入怎样改变竞争的位置。
4. 理解线程私有计数如何通过最后合并得到全局结果。
5. 比较同步开销与额外存储、合并工作之间的关系。

## 3. 实验内容

| 实现 | 怎样协调计数？ |
|---|---|
| Serial | 单线程直接计数。 |
| Critical | 所有共享更新进入同一个临界区。 |
| Atomic | 用原子操作完成某个桶的加一。 |
| Locks | 根据桶号选择一把分段锁，保护更新。 |
| Private | 每线程使用独立计数，结束后按桶合并。 |

默认比较三组输入规模、两种分布和不同锁数。`uniform` 将值分散到所有桶；`hotspot` 让大部分值落到桶 0。
