# Lab4：MPI 稀疏矩阵乘法

我们再次计算 Lab1 中的稀疏矩阵乘法。这一次，参与计算的是多个 MPI 进程，它们需要通过消息获得数据。

## 1. 实验背景

OpenMP 线程可以读取同一份 B。MPI 程序中的每个进程有自己的数据，不能直接通过普通指针读取另一进程的 B 行。

我们让每个进程保存 A 的连续行段，计算 C 的对应行段，并让 B 的行也分布在各进程中。要计算本地 `A[i,k] × B[k,:]`，必须先知道 B 的第 k 行由谁持有，再决定怎样获得它。

这引出三个问题：A 的工作怎样分配？B 要传输多少？等待数据时，是否有计算可以先做？

## 2. 实验目标

1. 理解 MPI 的进程、rank 和通信组。
2. 根据本地 A 的列索引判断需要哪些 B 行。
3. 比较完整数据交换与按需数据交换。
4. 理解非阻塞通信与本地计算的重叠过程。
5. 在相同输入下同时观察最大进程耗时和通信量。

## 3. 实验内容

| 实现 | 如何获得 B？ |
|---|---|
| Broadcast | rank 0 广播完整 B。 |
| Allgather | 各进程贡献自己的 B 行，所有进程收集完整 B。 |
| Halo | 只交换本地 A 所需的远程 B 行。 |
| Overlap | 发起按需交换后，先计算引用本地 B 的部分，再等待远程数据。 |

所有并行实现使用相同的本地分块计算内核，便于观察数据交换方式。输入包含 Lab1 的三种分布，并增加 `banded`，用于观察所需 B 行较集中的情况。

!!! note "一台电脑就能开始"
    `mpiexec` 可以在当前电脑启动多个进程。这样可以学习数据划分和通信接口；如果要研究多台主机的效果，还需要记录网络、主机和进程放置方式。
