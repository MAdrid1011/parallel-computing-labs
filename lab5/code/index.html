    Lab5 核心代码讲解¶

    Lab5 用一组计算电路完成稠密矩阵乘法。C++ 准备矩阵并驱动仿真，矩阵元素沿着下面的路径经过 RTL 模块：

    软件 DRAM 中的 A、B
    → read_dma 搬入输入块
    → scratchpad 保存 A、B
    → systolic_array 中的 PE 计算部分和
    → scratchpad 中的 C 累加部分和
    → write_dma 将完成的 C 块写回软件 DRAM

    顶层 matrix_accelerator 协调这些模块，决定当前处理哪个块、什么时候开始计算、什么时候写回。矩阵尺寸、分块尺寸、阵列尺寸和缓冲方式，分别控制这条计算路径中的不同部分。

    1. 完整矩阵、存储分块与计算阵列¶

    考虑 A、B 都为 8×8 的例子，输出 C 也是 8×8。设置 m=8、k=8、n=8，并使用：

    tile-m=4，tile-k=4，tile-n=4
array=4

    完整 C 有 64 个元素。tile-m=4、tile-n=4 把它分成 4 个 4×4 输出块：

    C = [ 左上 4×4 │ 右上 4×4 ]
    [─────────┼─────────]
    [ 左下 4×4 │ 右下 4×4 ]

    输入和当前输出块保存在片上暂存存储器 SPM 中。物理计算阵列由 array×array 个 PE 组成；PE 是执行乘加、保存部分和的小单元。这里 array=4，因此有 16 个 PE，一个阵列微块覆盖 4×4 个输出位置。

    完整矩阵表示问题有多大，存储分块表示 SPM 一次保存多大一块，阵列尺寸表示一次微块计算覆盖多少输出位置。三者可以取不同的值。

    2. 一个输出块沿 K 维分两组累加¶

    以 C 的左上 4×4 块为例，它使用 A 的前 4 行和 B 的前 4 列。每个输出都需要沿 K 的全部 8 个位置求和。因为 tile-k=4，输入分两组搬入：

    第 1 组：A[行 0～3，列 0～3] × B[行 0～3，列 0～3]
第 2 组：A[行 0～3，列 4～7] × B[行 4～7，列 0～3]

两组分别得到一个 4×4 部分结果，相加后得到 C 的左上块。

    对其中的 C[0,0]，假设 A 第 0 行和 B 第 0 列是：

    A 第 0 行：[1, 2, 1, 0 │ 2, 1, 0, 1]
B 第 0 列：[1, 1, 2, 1 │ 1, 2, 1, 1]

第 1 组：1×1 + 2×1 + 1×2 + 0×1 = 5
第 2 组：2×1 + 1×2 + 0×1 + 1×1 = 5
最终 C[0,0] = 5 + 5 = 10

    因此，tile-m 和 tile-n 决定当前计算哪些输出位置，tile-k 决定这些位置的求和分几组完成。改变 tile-k 后，每组的范围会变化，全部 K 项仍然要计算。

    matrix_q 选择正在搬 A 还是 B。搬 A 时，每行宽度为当前 K 分块长度；搬 B 时，每行宽度为当前 N 分块宽度。

    一次读数据拍有 64 位，可以携带 4 个 int16 元素，所以 ar_beats=(width+3)/4 计算一行需要几拍。spm_column=beat_q*4 表示这一拍放到哪一列，spm_lanes 表示其中有几个有效元素。

    r_valid 表示数据端提供了有效数据，r_ready 表示 DMA 可以接收。两者同时为 1，spm_write 才成立，将这一拍写入 SPM。当前组的 A、B 全部搬入后，控制器就可以让阵列读取它们。

    第 0 列从左边界取得 A，其余列从左邻居取得；第 0 行从上边界取得 B，其余行从上邻居取得。于是同一个 A 元素可以继续用于右边的输出，同一个 B 元素可以继续用于下边的输出。

    这些传递发生在时钟上升沿，数据逐步经过相邻单元。SPM 会错开不同行、列的边缘供数，让同一个 K 位置的 A、B 在各 PE 相遇。超出真实分块范围的输入保持 valid 为 0，边缘不足一个阵列大小的块也能正确计算。

    5. C 的 SPM 保存跨组累加的结果¶

    阵列完成当前组的计算后，顶层进入 STORE_C，把 PE 的部分和加到 C 的 SPM。下一组开始时，PE 可以清零，而此前的贡献继续保存在 C 的 SPM 中。

                    <= c_memory[(c_column+32'(lane))%ARRAY][c_row*COLUMN_GROUPS+(c_column+32'(lane))/ARRAY] + c_values[lane];

    处理一个新输出块时，c_zero 让对应的 C 区域清零。保存一组结果时，则执行“已有 C + 本次 PE 部分和”。刚才 C[0,0] 的完整过程为：

    开始这个输出块：C 的 SPM 中为 0
第 1 组完成：   0 + 5 = 5
第 2 组完成：   5 + 5 = 10
全部 K 组完成：将 10 与块中其他最终结果一起写回

    所有 K 组都处理完，顶层才启动 write_dma，把完整输出块写回软件 DRAM。C 使用 int32 元素，一个 64 位写数据拍最多携带两个输出；尾拍通过字节使能标记有效部分。随后控制器转到下一个输出块，重复这条路径，直到整个 C 完成。

    6. 分块尺寸与阵列尺寸的组合¶

    仍然计算同一个 8×8 的 C，保持 tile-k=4，比较下面三个配置：

    配置 SPM 中一个输出块 每个输出块中的阵列微块 K 分组
    tile-m=4，tile-n=4，array=4 4×4，整个 C 分为 4 块 1 个 4×4 微块 每块分 2 组
    tile-m=8，tile-n=8，array=4 8×8，整个 C 为 1 块 4 个 4×4 微块 每块分 2 组
    tile-m=8，tile-n=8，array=8 8×8，整个 C 为 1 块 1 个 8×8 微块 每块分 2 组

    第二个配置中，SPM 为一组输入保存 A 的 8×4 块、B 的 4×8 块，再让 4×4 阵列依次处理左上、右上、左下、右下四个输出微块。这组输入在微块之间继续使用，例如左上和右上微块都要用到 A 的前四行。

    第三个配置才把物理阵列扩大为 8×8，共 64 个 PE，使一个阵列微块覆盖整个 8×8 输出块。扩大 SPM 中使用的块与扩大物理阵列，会改变计算组织中的不同层次。

    如果只把 tile-k 从 4 改成 8，K 的两组就合成一组，PE 会在这一组中累加全部 8 项。输出块的行列范围仍由 tile-m、tile-n 决定。

    7. 单缓冲与双缓冲的输入安排¶

    缓冲方式决定何时搬入下一组 A、B。单缓冲使用同一个输入区域，当前组用完后才能覆盖它：

    搬入第 1 组 → 计算第 1 组 → 搬入第 2 组 → 计算第 2 组

    双缓冲使用两份输入区域。在缓冲 0 中的数据参与计算时，读 DMA 可以把下一组写入缓冲 1：

    缓冲 0：搬入第 1 组 → 计算第 1 组
缓冲 1：              搬入第 2 组 → 计算第 2 组

    顶层在当前输入就绪后，检查是否还有下一 K 组。使用双缓冲时，就向另一份缓冲发起预取：

    if (double_q && k_offset+tk_q<k_q) begin

        load_k <= k_q-k_offset-tk_q<tk_q ? k_q-k_offset-tk_q : tk_q;

    end

CLEAR_PE: begin step_q <= 0; store_row <= 0; state <= RUN_PE; end

    current_buffer 选择当前计算读取的输入，!current_buffer 选择另一份。两份区域分开，DMA 就不会覆盖阵列仍在使用的数据。当前组处理完后切换缓冲；只有下一份的 buffer_ready 已置 1，才允许阵列读取。

    两种缓冲方式都要完成两个部分和，并把 5 与 5 相加得到 10。双缓冲改变的是输入组的搬运与使用顺序。若 tile-k 已等于完整 K，当前输出块只有一组输入，就没有下一 K 组可以预取。

    8. 参数沿计算路径的对应位置¶

    参数 控制的内容 与其他参数的关系
    m、k、n 完整 A、B、C 的尺寸 决定最终要求出的矩阵
    tile-m、tile-n 当前输出块的行数、列数 一个块可交给阵列分成多个微块处理
    tile-k 每组输入覆盖的 K 长度 多组贡献要在 C 的 SPM 中相加
    array 物理 PE 阵列边长 选择已构建的 4×4、8×8 或 16×16 模型
    buffering 单缓冲或双缓冲的输入安排 可与不同分块尺寸、阵列尺寸组合
    spm-tile、spm-k 构建模型时确定的 SPM 容量 运行分块必须放得进这些存储区域

    统一参数 --tile 4 会同时把 tile-m、tile-k、tile-n 设为 4。单独改变某个方向时，使用对应的 --tile-m、--tile-k、--tile-n。例如增大输出块而保留两组 K 输入，可以设为 tile-m=8、tile-k=4、tile-n=8。

    模型为 A、B 各准备了两份物理缓冲，single 只使用其中一份，double 会交替使用两份。运行时选择更小的 tile 只改变本次使用的范围，存储容量仍由构建参数确定。
