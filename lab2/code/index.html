    Lab2 核心代码讲解¶

    Lab2 把矩阵的行、列交换。Serial、Naive 和 Tiled 都把每个输入元素放到同一个目标位置，变化的是遍历顺序和任务划分。用一个 4×4 矩阵，可以同时看到这两个变化。

    src/main.cpp 读取配置后调用 benchmark，由 generate_matrix 生成输入，并准备同样大小的输出数组。选择的内核负责把每个输入元素搬到转置位置：

    准备 input 和 output → 选择 kernel → 填写 output
                         ├─ serial
                         ├─ parallel_naive
                         └─ parallel_tiled

    1. 转置的元素对应关系¶

    输入 A                      输出 B
[  1   2   3   4 ]          [  1   5   9  13 ]
[  5   6   7   8 ]    →     [  2   6  10  14 ]
[  9  10  11  12 ]          [  3   7  11  15 ]
[ 13  14  15  16 ]          [  4   8  12  16 ]

    输入第 0 行的 1、2、3、4，成为输出第 0 列；输入第 1 行的 5、6、7、8，成为输出第 1 列。一般地，输入位置 (i,j) 对应输出位置 (j,i)。

    矩阵在内存中按行存放，连续排列为 1、2、3、4、5、6……。对于 n×n 矩阵，第 i 行第 j 列的数组下标是 i*n+j。串行实现因此写成：

    源码：Lab2/src/transpose_serial.cpp · L8–L10（节选）

    for (std::size_t i = 0; i < n; ++i)
    for (std::size_t j = 0; j < n; ++j)
        output.values[j * n + i] = input.values[i * n + j];

    外层循环固定输入行，内层循环依次读取这一行的元素。取出的值写到输出的第 j 行、第 i 列。所有实现都保留这个元素对应关系。

    2. Naive 把输入行交给不同线程¶

    串行实现由一个线程处理四行。Naive 把每一行作为一个任务，让多个线程共同完成：

    输入中的行任务               在输出中写入的位置
第 0 行：[ 1  2  3  4]   →   第 0 列
第 1 行：[ 5  6  7  8]   →   第 1 列
第 2 行：[ 9 10 11 12]   →   第 2 列
第 3 行：[13 14 15 16]   →   第 3 列

    这时有 4 个任务。设 threads=2，就由两个线程分担；每个线程可以执行不止一个任务。输入行不同，对应的输出列也不同，所以各任务不会写同一个元素。

    源码：Lab2/src/transpose_parallel.cpp · L15–L18（节选）

    omp for 分配外层的 i 循环，内层的转置赋值与串行版本相同。对于每个行任务，读取顺序仍是沿输入的一整行前进，写入位置则沿输出的一整列前进。

    3. Tiled 把二维区域作为任务¶

    设置 tile=2 时，输入沿行、列两个方向每隔 2 个元素划分一次，得到 4 个 2×2 块：

    输入 A 的块                  转置后输出 B 的块
[ 1   2 │ 3   4 ]            [ 1   5 │ 9  13 ]
[ 5   6 │ 7   8 ]            [ 2   6 │10  14 ]
────────┼────────     →      ────────┼────────
[ 9  10 │11  12 ]            [ 3   7 │11  15 ]
[13  14 │15  16 ]            [ 4   8 │12  16 ]

    左上块留在左上，右上块移动到左下，左下块移动到右上，右下块留在右下。每个块内部的元素也交换行列。例如输入左上块 [1,2;5,6] 会写成输出左上块 [1,5;2,6]。

    一个线程领取一个块后，会先完成这个块，再处理其他块。对左上块来说，读取顺序是 1 → 2 → 5 → 6；串行或 Naive 的行任务则会先读取 1 → 2 → 3 → 4。

    源码中的外两层循环选择块，内两层循环处理块中的元素：

    源码：Lab2/src/transpose_tiled.cpp · L15–L22（节选）

    #pragma omp for collapse(2) schedule(static) nowait
for (std::size_t bi = 0; bi < n; bi += tile)
    for (std::size_t bj = 0; bj < n; bj += tile) {
        const auto row_end = std::min(bi + tile, n);
        const auto column_end = std::min(bj + tile, n);
        for (std::size_t i = bi; i < row_end; ++i)
            for (std::size_t j = bj; j < column_end; ++j)
                output.values[j * n + i] = input.values[i * n + j];

    bi、bj 表示当前输入块的左上角。collapse(2) 把这两个块循环的组合交给线程。i、j 只在当前块范围内前进，最里面仍然执行原来的转置赋值。

    如果 n=5、tile=2，最后一行或一列的块只有 1 个元素宽。min 将块的结束位置限制在 n 以内，因此最后这些小块也会被完整处理。

    4. 分块后的数据访问顺序¶

    矩阵按行保存，缓存会一次带入某个位置附近的一段数据，这一段称为缓存行。程序很快访问相邻位置时，就有机会利用已经带入的数据。

    Naive 处理输入第 0 行时，会分别写输出的第 0、1、2、3 行；处理下一条输入行后，才回来写这些输出行的相邻列。

    Tiled 处理左上 2×2 块时，先写 B[0,0]、B[1,0]，接着就写 B[0,1]、B[1,1]。访问集中在两条输出行的局部区域，可以更早回到相邻元素。分块改变了元素被访问的顺序，矩阵的转置结果和元素总数都保持相同。

    5. 矩阵规模、块尺寸与线程分工¶

    配置 矩阵大小 计算任务 执行者
    Naive，n=4，threads=2 4×4 4 个行任务 2 个线程
    Tiled，n=4，tile=2，threads=2 4×4 4 个 2×2 块任务 2 个线程
    Tiled，n=4，tile=4，threads=2 4×4 1 个 4×4 块任务 只有一个块可分配

    因此，增大 tile 会让一个任务覆盖更多元素，同时减少块的数量；增大 threads 增加执行者，并不会自动产生更多块。上表最后一个配置就只有一个任务，其余线程没有其他块可以领取。

    这里的 tile 是二维块的边长：tile=2 形成 2×2 区域。Lab1 的 tile 则只指定输出列的宽度，行范围另由非零数分块决定。

    --kernel 在 Serial、Naive、Tiled 之间选择实现，--tile 参与 Tiled 的块循环。脚本中出现的 Tile16、Tile32 等名称，都是同一个 Tiled 内核使用了不同块边长；Naive 保持逐行处理的方式。
